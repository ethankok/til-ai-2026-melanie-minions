1. Executive Summary

AE is the autonomous Bomberman-style task. Our submitted service returns one action per tick for one controlled agent. The actual durable winner was not a neural policy. It was the hand-coded fixed-Novice heuristic planner, plus a lot of experiments proving which learned wrappers and tactical ideas did not transfer to hidden evaluation.

The leaderboard maximum, ppo-full-rl-v1-hybrid 0.638 / 0.847, should be preserved as official history, but it should not be used as evidence that PPO was responsible. Later forensic work showed the deployed hybrid image failed to load the legacy PPO checkpoint and silently fell back to AEManager, the rule-based heuristic planner.

After the qualifier deadline, we built a stricter evaluation methodology. The key discovery was that unpinned PYTHONHASHSEED made identical local AE runs drift by large amounts because some candidate scoring depends on Python set/dict iteration order. We added deterministic hash pinning and training/ae/multi_seed_eval.py, then re-ranked candidate configs. The best current local config for any future cloud variance-farming is:

AE_MODE=heuristic
AE_ITEM_MISSION_VALUE=80
AE_ITEM_RESOURCE_VALUE=40
AE_ENEMY_BASE_VALUE=100
AE_DIJKSTRA_BOMB_COST=7.0
PYTHONHASHSEED=0

That combo beats the calibrated baseline on every semifinals-relevant proxy suite except pressure2, where it trades away performance in mass-bomb chaos.

2. What AE Is

AE stands for Autonomous Exploration. It is a six-team, one-agent-per-team Bomberman-style environment on a 16x16 grid. Each round lasts up to 200 environment steps. Our agent can move, turn, stay, or place bombs. The objective is not just survival: reward comes from collecting mission/resource/recon tiles, damaging enemies, destroying enemy bases, and avoiding own-base destruction.

Qualifier AE score is the evaluator's reward score plus speed blend. The reward component is effectively total AE reward divided by rounds and by 1000. The challenge-level blended score is 75% reward/accuracy and 25% speed, with speed measured against a 30 minute cap for the whole test set.

Novice means fixed map. Advanced means varied maps. Almost all of our serious work focused on Novice/fixed-map behavior, because the qualifier leaderboard and many local gates used that geometry.

3. HTTP Schema, Observations, Actions

The official evaluator calls our Docker service on port 5005. The FastAPI wrapper in ae/src/ae_server.py handles /ae, /reset, and /health.

{
  "instances": [
    {
      "observation": {
        "agent_viewcone": "... 7 x 5 x 25 float32 ...",
        "base_viewcone": "... base-centered x 25 float32 ...",
        "direction": 0,
        "location": [x, y],
        "base_location": [x, y],
        "health": [60.0],
        "frozen_ticks": 0,
        "base_health": [100.0],
        "team_resources": [0.0],
        "team_bombs": 3,
        "step": 0,
        "action_mask": [1, 1, 1, 1, 1, 1]
      }
    }
  ]
}

The response must be exactly the prediction shape the server produces:

{"predictions": [{"action": 0}]}
Action idNameMeaningImportant legality detail
0FORWARDMove one cell in the current facing direction.Masked off when the target cell blocks movement.
1BACKWARDMove one cell opposite the current facing direction.Masked off when blocked.
2LEFTTurn 90 degrees counter-clockwise.Usually legal when active.
3RIGHTTurn 90 degrees clockwise.Usually legal when active.
4STAYDo nothing this tick.Only legal action while frozen.
5PLACE_BOMBPlace a bomb at the current cell.Requires team bomb stockpile.

Action mask rule: always obey action_mask. We repeatedly designed wrappers so an illegal policy action falls back to a legal heuristic action. A wrong JSON shape or illegal action can ruin an otherwise strong planner.

4. Glossary Of Terms

AEManager / heuristic
The rule-based planner in ae/src/ae_manager.py. It tracks map memory, bombs, enemy sightings, bases, items, danger cells, visit counts, and picks a target every tick. This is the strongest deployed behavior we have.
Policy
A neural network that directly predicts one of the six raw actions. In this repo it uses observation encoders and small CNN/MLP policy networks. Pure policy mode repeatedly underperformed hidden eval.
BC / behavior cloning
Supervised imitation learning. We collect states and actions from the heuristic and train a neural policy to copy it. BC was mainly a warm-start for PPO.
PPO
Proximal Policy Optimization. Our PPO trainer is training/ae/train_ppo.py. It improved some local proxies, but policy-loaded cloud submissions repeatedly collapsed into the ~0.41-0.47 band.
Hybrid
A wrapper where the neural policy proposes actions and the heuristic can veto unsafe or invalid ones. In this codebase, hybrid does not automatically mean the policy is truly active: if checkpoint loading fails, the server falls back to heuristic.
Silent fallback
The server catches missing-checkpoint and model-load errors and returns AEManager(). This kept submissions alive, but it also made PPO-tagged results misleading until we traced the actual runtime path.
Fixed-map shortcut
AE_HYBRID_FIXED_MAP_SHORTCUT lets HybridAEManager return the heuristic directly on detected Novice maps. It preserved high heuristic behavior but made PPO selection metrics meaningless unless disabled for explicit policy A/Bs.
Dijkstra / BFS / A*
BFS is unweighted shortest path. Dijkstra handles weighted cells, especially destructible-wall routes with bomb cost. A* adds a heuristic tie-break toward a goal. Our A* tiebreak was a small hail-mary and looked null on cloud.
Orientation-aware path
A path search over (x, y, facing), so turns cost time. It is more physically faithful, but it was net negative because our existing target-value penalties were tuned for plain grid distance.
Action mask
Length-6 binary vector saying which actions are legal this tick. Frozen agents only get STAY. Bomb placement requires available bombs.
Cloudsuite, pressure2, furnished gate
Local scripted-opponent suites in training/ae/opponents.py and validate_cloud_suite.py. cloudsuite is a hidden-eval proxy. pressure2 is mass-bomb pressure. The furnished gate weights several suites, including strong_realistic, base_rush_exploit, bracket_proxy, top_seed_proxy, defense_trap, and mixed.
PYTHONHASHSEED
A Python setting controlling hash randomization. Because AE target candidates can depend on set/dict iteration order, unpinned hash seed made local scores drift. We now pin or sample it deliberately.
Multi-seed eval
The stricter evaluator in training/ae/multi_seed_eval.py. It runs multiple hash seeds and simulation seeds, then reports weighted means and standard error.
Heuristic-A, B, C
Named heuristic env configs. A is aggressive enemy-base value and lower distance penalty. B is defense-first. C is item-farm weighted: mission/resource values raised, enemy-base value reset to 100. C later became the best ingredient in the current recommended combo.
Option hybrid
An 8-way macro-policy path. The learned model chooses an intent such as escape, rush base, base bomb, collect mission, collect resource, hunt enemy, or explore. Planner code executes the raw movement safely.
Tactical hybrid
A sharper 12-way tactical selector for semifinals. It chooses macros such as counter-rush, guard base lane, intercept base threat, bomb base threat, and stall when winning. The 400-game checkpoint looked locally useful under a gate; the 800-game follow-up exposed harmful transitions.
Macro hybrid
The new proper-hybrid implementation. It is planner-first: the fallback is the calibrated heuristic-C + bomb_cost=7.0 planner, while RL chooses 12-way tactical macros only. Runtime accepts learned macro deviations after minimal positive support, allowed-option, and executor-safety checks, while the trainer's outer save gate requires wrapper improvement versus the fallback. The first strict support gate deadlocked at zero accepted deltas, and executor-only admission was too broad.
Harm-aware gate
A tactical-hybrid safety gate that considers attempted count, positive rate, and net score delta, not just positive support count. The harm-aware 800-game analysis found zero positive-EV transition pairs under even permissive thresholds.
MCTS
Monte Carlo Tree Search style lookahead. Our mcts-light attempts were too slow or strategically wrong because simulated opponents were stationary while real opponents move.
M5 / Pandemonium
External reported high-score directions. M5 was a scripted-first cascade. Pandemonium's visible plan said PPO plus BFS fallback. We ported or analyzed the transferable pieces and concluded the missing value is in codebase-specific fallback arbitration and opponent/curriculum details, not generic PPO.

5. Runtime Architecture

Common request flow

  1. Evaluator posts one observation to /ae.
  2. ae_server.py checks mode using AE_MODE, then optional ae/src/.ae_mode, then default hybrid.
  3. If step == 0 or the evaluator calls /reset, the global manager is re-instantiated.
  4. The active manager updates its own memory and returns one integer action.
  5. The server wraps it as {"predictions": [{"action": action}]}.

Manager modes

ModeClass / fileWhat it doesStatus
heuristicAEManagerPure rule-based planner. No torch. Fastest and most reliable.protected baseline
hybridHybridAEManagerPolicy proposes; heuristic updates memory and vetoes unsafe choices.default but can fallback
policyPolicyAEManagerPure raw-action neural policy.rejected for cloud
option_hybridOptionHybridAEManager8-way learned option selector with heuristic execution.experimental
tactical_hybridTacticalHybridAEManager12-way tactical selector with support/confidence/harm gates.semifinals research
macro_hybridMacroHybridAEManagerPlanner-first 12-way macro policy. Defaults to C+bomb7 heuristic fallback and tries top-k learned tactical deviations through strict gates.trainer gate repaired
scripted_hybridScriptedHybridAEManagerM5-style scripted base attack first, heuristic fallback.calibrated loss

AEManager internals

  • Map memory: seen cells, walls, destructible walls, item sightings, enemy sightings, base locations, known bombs, visit counts.
  • Danger model: bomb blast cells for near-timer bombs, own-bomb escape targets, visible enemy bombs, predicted walk danger.
  • Pathfinding: BFS for normal grids, Dijkstra for fixed-Novice weighted routing, optional A* tie-break, optional orientation-aware search.
  • Target scoring: candidate value minus distance penalty, visit penalty, threat/path penalties. Candidate groups include enemy bases, items, defense cells, exploration frontiers, and opportunistic bomb targets.
  • Bomb safety: place bombs only when the planner can prove an escape path before detonation and the bomb has a useful target such as base damage, enemy hit, or wall clearance.

9. Current State

Current AE recommendation for a future cloud round: run pure heuristic with item-farm values plus a higher Dijkstra bomb traversal cost.

AE_MODE=heuristic
AE_ITEM_MISSION_VALUE=80
AE_ITEM_RESOURCE_VALUE=40
AE_ENEMY_BASE_VALUE=100
AE_DIJKSTRA_BOMB_COST=7.0
PYTHONHASHSEED=0

This configuration is not magic. It is a calibrated mean-improver in our latest local furnished gate, not a guaranteed cloud winner. The operational reason it is the best current bet is simple: it combines two independently positive local directions, preserved 82% additivity, and wins on bracket_proxy, top_seed_proxy, and defense_trap. It loses pressure2, so it is targeted at semifinals-like bracket scenarios rather than chaotic mass-bomb pressure.

The qualifier official result is closed. Do not rewrite that history: the protected max remains 0.638 / 0.847. The future-facing change is that we now know which config has the best measured local mean if AE opens again.

The proper-hybrid path is now implemented as AE_MODE=macro_hybrid plus training/ae/train_tactical_ppo.py. On 27 May, the trainer was repaired so wrapper_eval means the deployed heuristic-first macro wrapper, while the old standalone policy score is diagnostic only via --eval-ungated-policy. The first repaired full run showed a zero-accept deadlock, so top-k was fixed and support/harm thresholds were moved out of the default candidate gate. It still does not have a promotable trained checkpoint; treat it as the next engineering line to train and gate against the direct C+bomb7 heuristic.

11. Lessons Learned

  1. Verify the runtime path. Tag names are not proof. A hybrid-tagged submission can be pure heuristic if checkpoint loading fails.
  2. Pin or sample PYTHONHASHSEED. Unpinned hash order invalidated several old local sweeps. The correct modern gate is multi-hash aggregation.
  3. Local proxy gains are not enough for AE. PPO kept improving local metrics while hidden eval collapsed. Treat cloud or a carefully calibrated multi-suite gate as the authority.
  4. Short sweeps find false peaks. Many 4-round or 8-round wins vanished under paired 48-round or n=5 furnished gates.
  5. Heuristic rules degrade better than neural policies under hidden distribution shift. This is why fallback and planner-first arbitration mattered so much.
  6. Count-only tactical gates are unsafe. More data can make harmful transitions look supported. Use positive rate and net delta.
  7. External high-score recipes are incomplete without code. "PPO + BFS fallback" or "scripted-first" describes a family, not the exact arbitration, bomb timing, route tables, checkpoint, or opponent curriculum that produced the score.
  8. Re-rank known configs before inventing a new family. The current best future config came from calibrated re-ranking and composition, not from the bigger scripted/RL lines.
